# CANON LAWS

## 01 / AUTHORITY

Dawa chooses consequential changes.

Avalhla Core owns the system/runtime/CoBuilder operating context.
This repository is a bounded CrossWorld domain repository.

Do not copy `memory/auto-read/00_AI_COBUILD.json` here.

## 02 / CANON

One concept -> one canonical name -> one canonical artifact.

Filename = address.

`concept_id` = stable identity anchor.

A filename names a semantic role; presentation style belongs inside the artifact.

Aliases preserve history or compatibility. An alias is not a second concept or second artifact.

## 03 / LAYERS

Canonical record != evidence.
Canonical record != mapping.
Canonical record != card.
Canonical record != scene.
Canonical record != helper output.

D&D 5e is a mapping language. It does not define CrossWorld canon.

## 04 / RELATION

RELATION != AGENT.

## 05 / COLOR

Color may express mood, atmosphere, identity expression, or relation.

COLOR MAY SPEAK
!=
COLOR MAY PROVE

Color does not become identity, evidence, security classification, permission, or automatic action.

Avalhla keeps BLUE as an anchor while allowing expression to change.

## 06 / MAPPING

Mappings translate CrossWorld canon into another vocabulary.

Mapping does not rewrite the source record.

A D&D class, ability, skill, spell, item, or statistic is not CrossWorld canon merely because it appears in a mapping or card.

## 07 / PERSISTENCE

Human-authored canon is deliberate.
Helper output is evidence.
Generated views are derived.
No generated output silently becomes canon.

## 08 / REVIEW

Review can find, attack, contradict, and block.

Review does not authorize.
A passing test is evidence, not permission.

The repository uses an 8-pass DevilAsh review:

1. structure
2. semantics
3. provenance
4. boundaries
5. injection
6. mapping
7. persistence
8. devilash

Commit/push follows verification, diff, review, and the human gate.
